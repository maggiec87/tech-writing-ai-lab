Documentation Engineering explores the technologies, architectures, workflows, and engineering practices used to build and maintain modern documentation systems.

As documentation grows in size and complexity, writing alone is not enough. Teams need reliable ways to structure content, manage versions, reuse information, automate publishing, test quality, and maintain documentation throughout the product lifecycle.

This area focuses on treating documentation as an engineered system rather than a collection of independent files.

## What This Area Covers

- **Docs-as-Code:** Managing documentation with Git, code editors, branches, pull requests, and reviews.
- **Documentation Architecture:** Designing scalable structures for documentation sites and content repositories.
- **Content Reuse:** Building modular content systems and reducing duplication.
- **Structured Authoring:** Applying structured content models, topic-based authoring, and standards such as DITA.
- **Documentation Platforms:** Building and configuring documentation sites with tools such as Docusaurus and MkDocs.
- **Automation and CI/CD:** Automating documentation builds, validation, deployment, and release workflows.
- **Documentation Testing:** Checking links, code examples, formatting, navigation, and content quality.
- **Versioning and Release Management:** Managing documentation across product versions and releases.
- **Metadata and Governance:** Defining content ownership, taxonomy, lifecycle rules, and maintenance processes.
- **Documentation Analytics:** Using data to understand content usage and identify improvement opportunities.

## How This Area Is Organized

This topic is explored through three complementary approaches.

### Learn

Build technical knowledge of documentation systems, architectures, tools, and engineering workflows.

Topics include:

- Docs-as-Code Fundamentals
- Building Documentation Sites with Docusaurus
- Automating Documentation Builds with GitHub Actions
- Documentation Architecture
- Documentation Versioning
- Modular Documentation and Content Reuse
- Automated Documentation Testing
- DITA and Topic-Based Documentation
- Component Content Management Systems
- Content Metadata and Taxonomy
- Documentation Governance
- Structured Authoring
- Documentation Quality Automation
- Documentation Release Management
- Documentation Analytics

### Reviews

Investigate how organizations and open-source projects design and operate their documentation systems.

These case studies focus on publicly observable architectures, workflows, tools, and implementation practices. They examine why particular approaches are used, what works well, where trade-offs exist, and what other teams can learn from them.

Potential case study areas include:

- Documentation Platform Architecture
- Docs-as-Code Workflows
- Documentation Versioning Strategies
- Documentation Build and Deployment Automation
- API Documentation Systems
- Content Reuse and Modular Documentation
- Documentation Localization Workflows

Possible research subjects include the public documentation platforms and engineering practices of Stripe, Vercel, Cloudflare, GitHub, Microsoft, Kubernetes, and other organizations.

### Projects

Build, automate, test, or improve documentation systems through hands-on implementation.

Potential project areas include:

- Building a Documentation Site
- Creating an Automated Documentation Build and Deployment Pipeline
- Developing a Modular Documentation PDF Exporter
- Implementing Link and Content Validation
- Designing a Versioned Documentation Structure
- Creating a Reusable Content Component System
- Building Documentation Quality Checks

Projects may explore a new tool or workflow, reproduce a public engineering approach, or solve a practical documentation problem.

## Learning Approach

Documentation Engineering connects content management with software engineering practices.

The goal is to understand not only how documentation is written, but also how it is structured, built, tested, released, and maintained at scale.

The learning process follows three connected activities:

1. **Learn** the engineering concepts, architectures, and tools behind documentation systems.
2. **Review** real-world implementations to understand architectural choices and engineering trade-offs.
3. **Build** working systems and workflows that demonstrate practical engineering skills.

This approach develops the ability to design and maintain reliable documentation infrastructure, not just publish documentation pages.
